# Dicionário lógico de dados — MVP C4G

## Finalidade e estatuto

Contrato lógico para revisão funcional e técnica do MVP. Deriva de [`../decisions/future-data-model.md`](../decisions/future-data-model.md) e não define SQL, tipos físicos, índices ou migrations. A implementação UBI é apenas fonte de migração, conforme [`current-implementation.md`](current-implementation.md).

## Convenções comuns

### Notação

| Símbolo | Significado |
| --- | --- |
| `R` / `O` | Atributo obrigatório / opcional |
| `U` / `CU` / `—` | Único / parte de unicidade composta / sem unicidade |
| `PUB` | Público: pode ser publicado sem autenticação quando a regra funcional o permitir |
| `INT` | Interno: uso normal por utilizadores autorizados |
| `CONF` | Confidencial: acesso limitado por função e âmbito |
| `PII` | Dado pessoal |
| `SPII` | Dado pessoal sensível; não foi identificado nenhum atributo necessário ao MVP |
| `SEC` | Segredo; classe proibida nestas tabelas funcionais |
| `M` / `A` / `I` | Registo mutável / arquivável / facto ou versão imutável |

Cada atributo é descrito como `nome : tipo lógico [R|O, U|CU|—, classe]`. `semantic_code` é um código estável, independente da label apresentada. `json_typed` só é permitido para estruturas documentadas e validadas, nunca para ocultar invariantes relacionais.

### Campos transversais por perfil de ciclo de vida

| Perfil | Campos aplicáveis |
| --- | --- |
| `M` | `id: uuid_v7`, `created_at: timestamp_utc`, `updated_at: timestamp_utc`, `lock_version: integer`; `created_by`/`updated_by: uuid_v7` apenas quando a autoria tem valor funcional ou de auditoria |
| `A` | Campos de `M` mais `archived_at: timestamp_utc?`, `archived_by: uuid_v7?`, `archive_reason: text?` |
| `I` | `id: uuid_v7`, `created_at: timestamp_utc`; conteúdo não é atualizado, sendo corrigido por novo facto/versão |

- UUID v7 é gerado pela aplicação para entidades expostas, auditadas, sincronizadas ou referenciadas entre bases.
- Todos os instantes são UTC; fusos locais servem apenas para apresentação e regras de calendário explícitas.
- Labels configuráveis ficam separadas de códigos semânticos estáveis.
- Dinheiro usa `decimal`, código ISO 4217, natureza, data de referência, origem e precisão. Nunca usa ponto flutuante JavaScript.
- Snapshots indicados como imutáveis não são alterados quando a origem muda.
- Optimistic locking aplica-se a agregados `M`/`A` com edição concorrente; eventos e versões `I` não são editáveis.
- Entidades históricas não têm eliminação física automática. Arquivo, anonimização ou eliminação dependem de política aprovada e de ausência de `legal_hold`.
- IDs Keycloak são referências externas; credenciais, tokens, chaves R2, segredos Neon e chaves Resend não são campos funcionais.
- Metadados R2 residem na base da organização; os objetos físicos residem em buckets privados.

Não existem foreign keys distribuídas. Cada consumidor mantém `tenant_inbox_event`, aplica o evento idempotentemente e confirma processamento. Operações multi-base usam saga e estados intermédios explícitos, nunca uma transação distribuída presumida.
